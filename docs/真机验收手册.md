## 〇、当前环境结论（2026-10-10 更新）

- **已具备**：Docker 构建镜像 `gfa-android-build`（JDK17 + SDK 34 + NDK r26b + Gradle，NDK 走腾讯镜像）；已在容器内真实跑通 `gomobile bind`（`android/app/libs/gosvc.aar`，19MB）与 `gradle assembleDebug`，产出 **`android/app/build/outputs/apk/debug/app-debug.apk`（56MB）**，Kotlin 编译 0 error。
- **构建命令**（无需本机 JDK/SDK）：
  ```bash
  docker build -t gfa-android-build -f docker/android/Dockerfile docker/android
  docker run --rm -v "$PWD":/work -w /work/android gfa-android-build \
      gradle --no-daemon -x lint assembleDebug
  ```
- **仍缺（真机验收硬前提）**：① 一台通过 USB 接入的 Android 8.0+ 真机（宿主 PnP 当前无任何安卓设备）；② Windows 上需安装 `usbipd-win` 并把手机共享给容器（`winget install usbipd-win` → `usbipd list` → `usbipd bind --busid <id>` → `usbipd attach --wsl/docker ...`），或直接在装有 Android Studio + platform-tools 的机器用 `adb install` 安装本 APK。
- 满足上述任一路径后，按第三节用例执行、填第五节记录表即可。

## 一、环境准备（一次性）

### 1. 安装 JDK 17
- 推荐 Temurin JDK 17；安装后设置 `JAVA_HOME`，`java -version` 可显示 17。

### 2. 安装 Android SDK（command-line tools 即可）
需要组件：
- `platform-tools`（提供 `adb`）
- `build-tools;34.0.0`（或项目 `compileSdk` 对应版本）
- `platforms;android-34`
- 若涉及 gomobile：还需 `ndk;*` 并执行 `go install golang.org/x/mobile/cmd/gomobile@latest && gomobile init`。

设置 `ANDROID_HOME`，并把 `platform-tools` 加入 PATH。

### 3. 生成 Gradle Wrapper（项目缺 gradlew）
在 `android/` 目录用本机 gradle 或 Android Studio 执行一次：
```bash
gradle wrapper --gradle-version 8.7
```
生成 `gradlew` / `gradlew.bat` / `gradle/wrapper/*` 后提交入库，后续无需本机 gradle。

### 4. 真机与连接
- 一台 Android 8.0+（minSdk 26）真机；建议至少一台国产 ROM（小米/华为/OV）。
- 「设置→关于手机→连点版本号」开启开发者模式 → 打开「USB 调试」。
- USB 连接电脑，弹窗允许调试：
```bash
adb devices        # 出现设备号且状态 device 即正常
```

## 三、验收用例

> 每条均需：操作步骤 → 预期结果 → 证据（截图/录屏 + 必要时 logcat）。
> 服务端可在真机本地（gomobile）或远端 `cmd/server`；确认 App 的 base URL 指向可达服务。

### A. 稍后处理（snooze）
- **A1 微信来消息出现转述**：另一台设备向被测机微信发一条消息 → 预期：通知栏出现本 App「通知助手」转述（"{app}来消息"，含原文），**原微信通知仍在、未被取消**。
- **A2 三个 action**：转述通知上可见「10分钟后 / 1小时后 / 今晚」。
- **A3 点「10分钟后」**：点按 → 等 10 分钟（可用改系统时间或临时设短间隔验证）→ 预期：收到「管家提醒」高优通知，**内容为原消息原文**。
- **A4 今晚逻辑**：20:00 前点「今晚」→ fire_at 为当日 20:00；20:00 后点 → 次日 20:00。
- **A5 回查兜底**：断网点 action → 预期不崩溃、无误绑；恢复网络后匹配不到 event_id 时静默。

### B. 线索自动接住（clue）
- **B1 取件码**：向被测机发送含「【菜鸟驿站】您的取件码 8-7-6543」的通知/短信 → 预期：收件箱「线索」tab 出现 `pickup`，值 `8-7-6543`，可一键复制。
- **B2 验证码**：发「您的验证码为 482915，5 分钟内有效」→ `code=482915`。
- **B3 运单号**：发「您的快递单号 SF1234567890123 已发出」→ `tracking=SF1234567890123`。
- **B4 反例**：「会议在 3 楼 2 号厅，时间 14 点」→ 不应误判为线索。

### C. 语义搜索（search）
- **C1 有向量**：embedder 可用时，先产生若干通知，Web/App 收件箱搜「老王发我的地址」→ 预期：mode 徽标显示「语义」，命中原通知且排序合理。
- **C2 降级显式**：关闭/配错 embedder → 再搜 → 预期：徽标显示「关键词」，结果为 LIKE 命中，**无静默失败**。
- **C3 空结果**：搜不存在内容 → 优雅空态，不报错。

### D. 等到了（watch）
- **D1 创建并命中**：收件箱「等待中」新建 title=老王、keyword=地址 → 再让微信收到含「地址」的消息 → 预期：收到高优「等到了：…」通知并附原文，该 watch 状态变 fired。
- **D2 来源限定**：新建指定 source_pkg 的 watch，从其他 App 发同关键词 → 不触发。
- **D3 取消**：列表点取消（DELETE）→ 状态 cancelled，后续不再触发。

### E. 链路与稳定性（专项）
- **E1 防回环**：本 App 自身发出的通知不得再次上报（无重复嵌套）。
- **E2 60s 去抖**：同 pkg+title+text 连续通知，60s 内只入库一次。
- **E3 重启存活**：重启手机 → 前台服务/自启正常，未到期 snooze 仍能到点触发。
- **E4 ROM 保活**：国产 ROM 上观察 24–72h，记录被系统杀后台次数与到点触达成功率。
- **E5 耗电/内存**：记录 24h 耗电（mAh）与常驻内存。
