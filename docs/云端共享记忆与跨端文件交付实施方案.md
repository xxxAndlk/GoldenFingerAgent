# GoldenFingerAgent 云端共享记忆与跨端文件交付实施方案

> 版本：实施稿 v1.0  
> 日期：2026-11-04  
> 状态：设计待实施，本文不代表功能已经完成  
> 目标：让电脑与手机使用同一份长期记忆，并补齐“电脑处理文件后显式交付到手机”的完整链路  
> 前置阅读：`AGENT.md`、`docs/架构设计与模块功能.md`、`docs/SuperAgent完整修复实施方案.md`

---

## 1. 结论与实施边界

### 1.1 核心结论

1. “同一个管家”应统一为同一个 `owner_user_id` 下的共享长期记忆，不要求电脑和手机共用无限聊天 Session。
2. 云端提供记忆 API，电脑和手机分别通过 `RemoteMemory` 存取；不做两个 SQLite 文件的双向同步。
3. 现有中继继续负责配对、连接和指令转发；记忆与文件交付使用 HTTPS API，可与中继共用域名，但不混入 WebSocket 业务报文。
4. 当前已经能读取、写入电脑文本文件，也有 Artifact 版本模型，但尚未形成“任意文件 Artifact → 云端临时交付 → 手机下载”的闭环。
5. A2A 用于金手指与外部 Agent 之间委派任务、交换文件产物，不作为手机下载文件的传输协议。
6. 文件只在用户明确要求交付时上传云端临时交付区；文件正文不进入长期记忆，云端记忆只保存必要的交付事件摘要。

### 1.2 第一阶段交付范围

- 云端共享 `mem_episode` 与 `mem_edge`。
- 电脑、手机 `RemoteMemory`。
- 本地持久 Outbox，网络恢复后幂等续传。
- 普通回答时按当前问题自动召回共享记忆。
- 云端记忆健康状态、遗忘和旧数据迁移。
- 本地 Artifact 支持文本与二进制文件快照。
- 显式文件交付、云端临时存储、手机下载、哈希校验和交付回执。
- A2A v0.3/v1.0 版本适配，以及外部 Agent 文件 Artifact 接收入库。

### 1.3 明确不做

- 不统一所有聊天 Session，不把全部历史塞入模型上下文。
- 不建设 PersistentAgent、数字员工或多 Agent 自由通信体系。
- 不把提醒、WorkTask、聊天数据库和本地设置一次性全部搬上云。
- 不默认上传截图、微信原文、电脑文件、命令输出和凭据。
- 不让云端直接执行电脑或手机操作。
- 不通过中继 WebSocket 传输大文件，不把 Base64 文件塞进聊天结果。
- 不把云端临时交付区当作永久网盘。
- 不让手机自动打开来源不明的文件。

## 2. 当前实现核对

### 2.1 已有能力

| 能力 | 当前实现 | 可复用部分 |
|---|---|---|
| 长期记忆端口 | `internal/memory/provider.go` 定义 `Append/Search/Forget/Health` | 可增加 HTTP Provider |
| 原生记忆 | `internal/memory/native.go` | 云端直接复用抽取、检索、失效和遗忘逻辑 |
| 记忆证据 | `mem_episode`、`mem_edge` | 云端继续使用相同数据语义 |
| 电脑文本读取 | `internal/agent/system_tools.go` 的 `read` | 最大 8 MiB，拒绝二进制 |
| 电脑文本写入 | `write` | 单次最大 1 MiB，修改前要求先读 |
| 电脑命令 | `bash` | 可执行转换工具或调用专业程序，但必须受任务授权约束 |
| Artifact | `internal/worktask/artifact.go` | 已有不可变版本、哈希、验收和来源 |
| Artifact 下载 | `GET /api/artifacts/{id}/versions/{version}/download` | 可复用 owner 校验与版本语义 |
| 手机远程指令 | relay → 电脑 `/api/chat` 或 `/api/jobs` | 保留任务提交、查询和取消 |
| A2A | `internal/agenthub/a2a.go` | 已有 Agent Card、鉴权和任务调用基础 |

### 2.2 当前缺口

1. `BuildContext` 当前只组装本地人物、事实和片段，没有根据本轮问题自动检索 `longTerm`；仅增加 RemoteMemory 并不能保证回答时使用云端记忆。
2. `mirrorEpisode` 调用后端失败时只记录日志，没有持久重试；直接改 HTTP 会因网络波动丢失云端写入。
3. Artifact 当前版本实际写入 `ContentText`、`text/plain` 和 `vN.txt/.code`，下载也返回文本字节，不是通用二进制文件容器。
4. relay `ResultPayload` 只有回复、任务状态与事件，没有 Artifact/Delivery 引用。
5. 电脑 Artifact 下载接口位于本机 HTTP 服务，不代表手机已经能通过公网中继下载。
6. A2A 当前只提取文本 Part，没有文件 Artifact 模型，也不支持 URL/Raw 文件内容。
7. 当前 A2A 代码发送 `A2A-Version: 1.0`，但仍使用旧式 `message/send`、`kind:text` 和小写状态；正式 v1.0 已改为统一 Part、成员判别和新枚举，必须先做版本兼容，不能直接叠加文件字段。

### 2.3 “打开电脑文件编辑后发到手机”现在能否完成

- **文本读取和写入：可以。**
- **把文本作为本地 Artifact 保存：基本具备。**
- **通用二进制文件 Artifact：尚未具备。**
- **任意桌面软件的可靠 GUI 打开与编辑：不能仅凭现有 read/write 承诺；应通过专用工具、BMA 或其他 Agent 完成。**
- **把文件交付到手机：尚未形成闭环。**

因此该需求需要新增交付链路，但不需要重写已有文件工具和 WorkTask。

## 3. 总体目标架构

```text
                           同一个 HTTPS 域名
                        https://cloud.example.com
                                    │
              ┌─────────────────────┼─────────────────────┐
              │                     │                     │
         /relay、WebSocket     /api/memory/v1       /api/delivery/v1
         现有 relay 服务        cloudserver           cloudserver
         配对与指令转发         记忆模块               文件交付模块
                                    │                     │
                              mem_episode/mem_edge    临时文件存储
                              NativeMemory             TTL 与哈希校验
                                    │                     │
              ┌─────────────────────┴─────────────────────┐
              │                                           │
          电脑端                                        手机端
      TurnService                                  TurnService
      RemoteMemory                                 RemoteMemory
      Memory Outbox                                Memory Outbox
      read/write/bash                              语音与手机操作
      ArtifactService                              Delivery Inbox
      Delivery Uploader                            HTTPS 下载与哈希校验
              │                                           │
              └──── 外部 Agent／BMA／A2A 文件产物 ─────────┘
```

### 3.1 云端服务命名与部署

新服务统一使用：

```text
cmd/cloudserver/
internal/memorycloud/
internal/deliverycloud/
```

第一阶段只启用记忆模块，后续在同一进程加入交付模块，避免先叫 `memoryserver`、加入文件后再改名。

现有 `cmd/relay` 保持独立。云端模块与 relay 可以共用域名和设备身份基础设施，但不共享业务数据库职责。

### 3.2 数据主权

- 云端是**共享长期记忆的主副本**。
- 电脑本地文件是原始文件来源，Artifact 是不可变快照。
- 云端交付区只是指定文件版本的**临时传输副本**。
- 本地聊天、WorkTask 和执行状态仍由原设备负责。
- 云端不可用时，聊天与本地执行继续，共享记忆和跨端下载明确降级。

## 4. 云端共享记忆设计

### 4.1 云端模块

```text
cmd/cloudserver/main.go          服务装配、配置、启动与优雅关闭

internal/memorycloud/server.go   记忆路由
internal/memorycloud/auth.go     设备鉴权与 owner 解析
internal/memorycloud/handlers.go episodes/search/forget/health
internal/memorycloud/devices.go  设备创建、撤销与 scope 校验
```

云端复用：

```text
internal/memory.Native
internal/store.LongTermRepo
mem_episode / mem_edge
现有模型抽取、向量、关键词、时效、冲突和遗忘逻辑
```

云端启动自己的 `Native.Start(ctx)`。第一版使用单进程和 SQLite WAL，数据文件与 relay 分离；规模确有需要时再迁移 PostgreSQL，不提前分布式化。

### 4.2 设备与授权

新增云端设备表：

```text
cloud_device
├─ id
├─ owner_user_id
├─ device_name
├─ token_hash
├─ scopes_json
├─ created_at
├─ last_seen_at
└─ revoked_at
```

设备由服务器管理命令创建：

```bash
cloudserver device create --owner luokun --name desktop \
  --scopes memory:read,memory:write,delivery:read,delivery:write
cloudserver device create --owner luokun --name android \
  --scopes memory:read,memory:write,delivery:read
```

规则：

- Token 使用高熵随机值，只在创建时显示一次，数据库只存哈希。
- owner 从 Token 对应设备解析，不信任请求体自报的 `owner_user_id`。
- 电脑和手机使用不同 Device ID 与 Token，可分别撤销。
- 每个 API 同时校验 owner 和 scope。
- 日志不记录 Token、完整记忆正文和文件内容。
- 公网仅开放 HTTPS。

### 4.3 写入 Episode

```http
POST /api/memory/v1/episodes
Authorization: Bearer <device-token>
Content-Type: application/json
```

```json
{
  "source_id": "chat:7d34f4a6-...",
  "text": "以后阶段总结尽量简短。",
  "source": "chat",
  "role": "owner",
  "reference_time": "2026-11-04T18:40:00+08:00",
  "content_hash": "sha256:..."
}
```

响应：

```json
{
  "source_id": "chat:7d34f4a6-...",
  "status": "accepted"
}
```

约束：

- 逻辑幂等键为 `UNIQUE(owner_user_id, source_id)`。
- 现有 `mem_episode.source_id` 是全局主键，不能只在文档中声明复合唯一约束。云端入库时保存为 `stored_source_id = cloud:<owner>:<original_source_id>`，NativeMemory 使用命名空间后的 ID，API 返回时再映射为原始 SourceRef。
- 新增 `cloud_episode_meta`，保存 owner、原始／存储 SourceID、Device ID、内容哈希和删除时间；重复请求与冲突必须查询该表判断。
- 相同 SourceID、相同哈希返回 `duplicate`，客户端视为成功。
- 相同 SourceID、不同内容返回 `409`，不得覆盖，客户端进入异常状态。
- 已按 SourceID 遗忘的记录返回 `410 Gone`，其他设备尚未发送的相同事件不能把记忆重新上传复活；重新记录必须产生新 SourceID。
- 正文上限 64 KiB，不接收文件和截图。
- `role` 仅允许 `owner/contact/system`，联系人内容不能记成机主意愿。
- Episode、元数据与遗忘 Tombstone 在同一云端事务中维护，再异步抽取；跨端事实召回允许存在短暂处理延迟。

### 4.4 检索

```http
POST /api/memory/v1/search
```

```json
{
  "query": "我喜欢的总结格式",
  "limit": 8
}
```

返回 `MemoryFact` 列表，包含：

- 不透明 Fact ID。
- 事实正文。
- 有效与失效时间。
- SourceRefs。
- confirmed/inferred/conflicted 等状态。

云端负责向量、关键词、时效和历史过滤所需的基础检索。第一版不另设 `/context`：Search 结果就是共享长期记忆；当前会话和 WorkTask 上下文仍由端侧组装。

### 4.5 遗忘

```http
POST /api/memory/v1/forget
```

支持 `source_id` 或 `fact_id`。

要求：

- 删除对应 Episode、派生 Edge、向量与索引。
- 清除本机相同 SourceID 的未发送 Outbox。
- 删除失败必须返回错误，不能只隐藏检索结果。
- 旧本地迁移备份不随云端请求自动删除，界面必须单独说明和处理。

### 4.6 健康状态

```http
GET /api/memory/v1/health
```

只返回 Ready、Backend、待抽取数、失败数等健康信息，不返回正文。

## 5. 端侧 RemoteMemory 与可靠同步

### 5.1 RemoteMemory

新增：

```text
internal/memory/remote.go
internal/memory/remote_test.go
```

实现现有 `LongTermMemory`：

- `Append`：先写本地持久 Outbox，再触发后台上传。
- `Search`：实时查询云端；失败由上层降级，不伪造成无记忆。
- `Forget`：调用云端删除，并清理对应待发事件。
- `Health`：报告云端可达性、待发数、失败数和最近同步时间。

### 5.2 本地 Memory Outbox

新增本地表：

```text
memory_sync_outbox
├─ source_id
├─ owner_user_id
├─ payload_json
├─ content_hash
├─ status
├─ attempts
├─ next_retry_at
├─ last_error
├─ created_at
└─ sent_at
```

约束与策略：

- `UNIQUE(owner_user_id, source_id)`。
- Outbox 落盘后才算“可靠接受待同步”，不阻塞聊天主流程。
- 网络错误、429、5xx 指数退避，尊重 `Retry-After`。
- `duplicate` 标记成功。
- 400、409 停止自动重试并显示数据异常。
- 401、403 暂停同步，要求重新授权。
- 服务重启后继续，日志不输出完整正文。

### 5.3 云模式读写原则

- 云模式启用后，云端是唯一长期记忆主后端，不再同时运行本地 Native 做双写抽取。
- 本地 Native 保留为独立本机模式和迁移工具，不作为云模式的影子主库。
- 云端检索失败时，仍可使用当前会话和本地旧有人物、事实等上下文，但界面显示“共享记忆不可用”。
- 网络恢复后只补传 Outbox，不做整库对撞。

## 6. 自动记忆召回改造

### 6.1 查询感知的上下文构建

在 `internal/memory` 增加：

```go
BuildContextForQuery(
    ctx context.Context,
    ownerID string,
    userType string,
    tz string,
    query string,
    budgetTokens int,
) (string, error)
```

处理顺序：

1. 加入用户类型与时区。
2. 用当前问题调用 `longTerm.Search`。
3. 加入“相关长期记忆”区块，并为共享记忆预留预算。
4. 补充本地人物、事实和最近笔记。
5. 按事实正文、ID 和来源去重。
6. 在总 Token 预算内裁剪，保留状态和时间信息。

### 6.2 PromptBuilder 接入

- 从 Session 取最新用户问题，调用 `BuildContextForQuery`。
- 保留原有无查询 `BuildContext` 作为兼容包装。
- 记忆继续放在动态用户上下文，不进入稳定系统前缀，避免破坏 DeepSeek 前缀缓存。
- 检索超时不能阻断整轮回答。
- `search_memory` 工具继续保留，用于主动深查，不作为自动召回的替代品。

## 7. 配置、界面与旧数据迁移

### 7.1 配置

```json
{
  "cloud_memory": {
    "enabled": true,
    "base_url": "https://cloud.example.com",
    "device_id": "desktop-01"
  }
}
```

Token 不写入导出文件，优先使用 Windows 安全存储和 Android Keystore；不得进入日志、聊天正文或模型工具结果。

设置页提供：

- 云端共享记忆开关与地址。
- “使用中继地址”快捷填充，但不强制绑定。
- 设备名称、Device ID、Token 与 scope。
- 测试连接、最近同步、待发和失败数量。
- 暂停同步、重新授权和撤销设备。
- 首版保存后重启生效的明确提示，不伪装热切换。

### 7.2 旧数据迁移

1. 先选电脑作为主旧库，不自动对撞电脑与手机全部旧数据。
2. 暂停电脑新记忆写入，在一致快照中导出 `mem_episode` 和 `mem_edge`。
3. 导出文件包含 `schema_version`、owner、时间、SourceRefs、状态、向量和内容哈希。
4. 云端停止写入，在事务中导入并校验数量、引用、confirmed/conflicted 状态及有效时间；导入时同时生成 owner 命名空间 SourceID 和 `cloud_episode_meta`，并同步改写 SourceRefs。
5. 云端 Embedder 的模型与维度必须与导出向量一致；不一致时不得混用旧向量，应清除待重建向量并通过原 Episode 重新生成。
6. 启动云端检索，先让电脑切换 RemoteMemory 验收，再接入手机。
7. 手机旧库先备份，确有需要的记忆再审核去重导入。
8. 本地旧数据不自动删除；云端验收后由用户单独决定是否清理迁移副本。

## 8. 本地 Artifact 通用文件化

### 8.1 目标

把当前“文本内容版本”扩展为“不可变内容版本”，同时支持文本与文件，不改变已有 Artifact ID、版本 CAS、验收和 SourceRefs 语义。

### 8.2 数据扩展

为 `artifact` / `artifact_version` 补充或明确：

```text
storage_kind       text | file
original_name      原始文件名
mime_type          服务端检测结果与声明值
size_bytes         文件字节数
content_hash       内容 SHA-256
relative_path      Artifact 根目录内的相对路径
source_kind        local_path | a2a | generated | external_ref
source_ref         来源 Agent、Task 或本地授权引用
```

文件版本保存规则：

1. 根据用户明确路径或任务 Grant 校验源文件。
2. 解析符号链接与真实路径，防止授权后换目标。
3. 在版本创建时复制到 Artifact 根目录，形成不可变快照。
4. 写入临时文件、计算哈希、校验大小后原子重命名。
5. 数据库版本与文件快照必须一致；失败不得留下可下载的半成品。
6. 源文件之后变化不影响旧 Artifact 版本。
7. 文本 Artifact 保持兼容，不强制迁移历史版本。

### 8.3 新增 Agent 工具

```text
create_file_artifact
  输入：task_id、path、title、change_summary
  行为：从已授权本地文件创建不可变 Artifact 版本

deliver_artifact
  输入：artifact_id、version、target_device_id
  行为：校验 Grant，创建交付任务并进入持久上传 Outbox

open_file（可选，独立于交付）
  输入：path
  行为：请求用户确认后由电脑系统默认程序打开
```

`open_file` 只负责可见打开，不代表已可靠控制对应 GUI。Office、设计文件等复杂编辑应委派给具备相应能力的工具或 Agent。

## 9. 跨端文件交付协议

### 9.1 为什么不走 WebSocket 或长期记忆

- 当前 relay 报文有大小限制，文件 Base64 会放大流量并阻塞指令通道。
- relay 当前没有桌面主动推送和持久文件存储语义。
- 手机需要的是可恢复 HTTPS 下载、哈希校验和过期删除，而不是聊天消息里的隐藏附件。
- 长期记忆只记录“哪个文件版本已交付”等摘要，不保存文件正文。

### 9.2 云端临时交付区

默认策略：

- 仅 `deliver_artifact` 明确授权的版本上传。
- 单文件默认上限 100 MiB，可配置。
- 默认保留 72 小时，可配置；过期物理删除。
- 云端只传输和存储，不做向量索引、事实抽取或内容理解。
- 第一版使用服务器本地磁盘临时目录＋原子重命名；后续可替换为对象存储，API 不变。
- 可执行文件、脚本和快捷方式默认拒绝，确有需要时要求额外确认。

### 9.3 Delivery API

```text
POST   /api/delivery/v1/artifacts
GET    /api/delivery/v1/inbox
GET    /api/delivery/v1/artifacts/{delivery_id}
GET    /api/delivery/v1/artifacts/{delivery_id}/content
POST   /api/delivery/v1/artifacts/{delivery_id}/ack
DELETE /api/delivery/v1/artifacts/{delivery_id}
```

上传请求包含：

- `Idempotency-Key`。
- Artifact ID、Version、目标 Device ID。
- 原始文件名、MIME、大小、SHA-256。
- multipart 文件流。

规则：

- 上传先写临时文件，校验实际大小和哈希后原子入库。
- 相同幂等键、相同哈希返回原 Delivery；不同内容返回 409。
- 下载必须校验目标设备、owner 和 `delivery:read`，不能仅凭公开 URL。
- Content-Disposition 文件名经过清理，下载支持 Range 作为后续增强。
- ACK 只证明手机已完整接收并校验，不伪造成用户已经打开或验收。
- DELETE 撤销下载并删除云端临时副本，不删除电脑 Artifact。

### 9.4 电脑 Delivery Outbox

新增持久上传任务：

```text
artifact_delivery_outbox
├─ idempotency_key
├─ owner_user_id
├─ artifact_id
├─ artifact_version
├─ target_device_id
├─ status
├─ attempts
├─ next_retry_at
├─ last_error
├─ delivery_id
├─ created_at
└─ completed_at
```

网络失败、电脑重启后继续。文件哈希或版本变化必须创建新交付，不允许上传途中替换内容。

### 9.5 Relay 结果扩展

中继协议升级为 v2，在 Hello 中协商版本；v2 新增可选字段，v1 对端继续按原协议处理且不会收到 ArtifactRef。服务端与双端在迁移期必须同时接受 v1，不能只把常量改成 2 后切断旧端：

```go
type ArtifactRef struct {
    ArtifactID string `json:"artifact_id"`
    Version    int    `json:"version"`
    DeliveryID string `json:"delivery_id,omitempty"`
    Name       string `json:"name"`
    MIME       string `json:"mime_type"`
    Size       int64  `json:"size_bytes"`
    SHA256     string `json:"sha256"`
}

type ResultPayload struct {
    // 保留现有字段
    Artifacts []ArtifactRef `json:"artifacts,omitempty"`
}
```

- Relay 只传元数据，不传公开长期 URL，不传文件正文。
- 同步聊天结果和异步任务状态都可带 ArtifactRef。
- 手机也可直接查询云端 Delivery Inbox，因此不依赖桌面主动推送才能找到文件。
- 旧协议端继续显示文本回复；新协议端显示文件卡片。
- 版本升级必须有兼容测试，不能静默改变旧字段语义。

### 9.6 手机端

- 共享 Web UI 增加“交付物”列表与文件卡片。
- Android 下载到 App 私有目录，校验 SHA-256 后显示完成。
- 用户主动选择“打开／分享／保存到系统文件”。
- 不自动执行文件，不自动安装 APK，不自动运行脚本。
- 下载中断保留失败状态并允许重试；只有完整校验后才发 ACK。

### 9.7 与共享记忆联动

交付完成后写入一条不含文件正文的记忆事件，例如：

```text
2026-11-04，电脑把《项目说明》Artifact v3 交付到 android-01，
文件哈希为 sha256:...，手机已确认接收。
```

SourceRef 指向 Artifact/Delivery ID。这样电脑或手机之后都能知道交付事实，但不会把文件内容注入模型。

## 10. A2A 文件产物接入

### 10.1 A2A 的职责

A2A 负责：

- 金手指把编辑、转换、分析等任务委派给外部 Agent。
- 外部 Agent 返回文本和文件 Artifact。
- 金手指把文件 Artifact 转为本地 Artifact，再按用户指令交付手机。

A2A 不负责：

- 替代 relay 的手机连接。
- 替代 Delivery API 的手机下载。
- 自动共享金手指的内部记忆、工具权限或设备 Token。

### 10.2 先修版本协商

官方 A2A v1.0 与 v0.3 在 Part、Role、TaskState 和方法命名上存在不兼容变化。当前适配器不能继续用同一套旧报文同时声明 v1.0。

新增：

```text
internal/agenthub/a2a_codec.go
internal/agenthub/a2a_v03.go
internal/agenthub/a2a_v1.go
```

规则：

- 从所选 AgentInterface 的 `protocolVersion` 选择 Codec。
- v1.0 使用统一 Part：`text`、`url`、`raw`、`data`，以及 `mediaType`、`filename`。
- v0.3 保留 `kind:text/file/data` 和对应文件结构。
- 按版本处理 Role、TaskState 和方法名。
- Agent Card 未声明版本时允许端点配置显式兼容版本，不默认把旧报文标成 1.0。
- 保留现有 BMA 兼容路径，用 v0.3/v1.0 合同测试防止升级后 BMA 无法调用。

### 10.3 文件 Artifact 模型

扩展 `Invocation`，不再只有 `Output`：

```go
type AgentArtifact struct {
    ID         string
    Name       string
    MediaType  string
    Size       int64
    SHA256     string
    ExternalURI string
    LocalPath  string
}

type Invocation struct {
    // 保留现有字段
    Artifacts []AgentArtifact `json:"artifacts,omitempty"`
}
```

处理规则：

- 文本结果仍进入 Output，行为向后兼容。
- v1.0 `url` 与 v0.3 URI 文件统一转成 ExternalURI。
- 小文件 Raw/Bytes 可在严格大小限制内解码入库；大文件优先 URI 或上传式交换。
- 外部 URI 是不可信输入，不能自动访问内网、本机地址或任意重定向目标。
- 下载外部 URI 需要独立授权、HTTPS、大小与超时限制，并重新计算本地 SHA-256。
- `delegate_agent` 只返回 URL 文件元数据，不继承委派授权自动下载；实际下载必须调用 WorkTask 专用的 `download_agent_artifact`，由工具门禁校验匹配 `external_uri` 等参数的独立 ActionGrant。
- 不向外部 Agent 转发云端设备 Token，也不把内网凭据附加到 URI 请求。
- 文件落为本地 Artifact 后记录 Agent ID、外部 Task ID 和原始引用。

### 10.4 输出模式

当前只声明 `text/plain`。文件任务应根据 Agent Card 与任务需求声明可接受的媒体类型；不支持文件输出的 Agent 应明确返回文本或能力错误，不能把无文本结果统一误报为“没有结果”。

## 11. 端到端流程

### 11.1 手机要求电脑编辑并回传文件

```text
手机：“把电脑 D:\docs\项目说明.md 精简后发到手机。”
  ↓ relay command/job
电脑创建／恢复 WorkTask，校验文件与交付 Grant
  ↓
read → 修改副本或原文件（按用户要求）→ create_file_artifact
  ↓
生成 Artifact v3：不可变快照、文件名、大小、SHA-256
  ↓
deliver_artifact(target=android-01)
  ↓
Delivery Outbox → HTTPS 上传云端临时交付区
  ↓
任务结果／Delivery Inbox 返回 ArtifactRef，不传文件正文
  ↓
手机 HTTPS 下载 → 校验大小与 SHA-256 → ACK
  ↓
用户主动打开／分享／保存；云端只记录交付摘要到共享记忆
```

任务验收、Artifact 验收、云端上传完成、手机下载完成是四个不同状态，界面不得混为一谈。

### 11.2 外部 Agent 编辑后回传

```text
手机／电脑 → 金手指 WorkTask
  → A2A 委派 BMA／其他 Agent
  → 外部 Agent 返回文本＋文件 Artifact
  → 版本化 Codec 解析
  → 文件授权获取与本地 Artifact 入库
  → 用户确认 deliver_artifact
  → 手机下载
```

## 12. 安全与隐私不变量

1. 云端 owner 永远由设备凭据解析，不能由请求体切换。
2. 本机 HTTP Artifact 下载接口不直接暴露公网。
3. 文件源路径、读取、编辑、外部下载和跨端交付分别受 Grant 限制。
4. Grant 绑定 Artifact 版本与内容哈希；内容变化需重新授权。
5. 文件复制使用 Artifact 根目录，不允许 `..`、符号链接逃逸或任意服务端路径下载。
6. A2A 返回内容始终是数据，不得借文件 URI、文件名或 metadata 注入指令。
7. 不将文件正文、云端 Token、模型密钥写入长期记忆。
8. 云端交付区默认短期保存，过期删除任务必须有可观测日志与测试。
9. 删除 Artifact、撤销 Delivery、删除共享记忆是不同操作，分别定义影响范围。
10. 云端记忆检索和文件上传失败都不能阻断基本聊天与本地急停能力。

## 14. 验收清单

### 14.1 共享记忆

| 场景 | 通过标准 |
|---|---|
| 电脑写偏好，手机询问 | 手机普通回答自动使用同一偏好 |
| 手机写事项，电脑询问 | 电脑能检索并给出来源 |
| 同一事件上传 10 次 | 只有一个 Episode，不重复抽事实 |
| 断网写入后重启 | Outbox 保留，联网后续传 |
| 云端不可用 | 聊天继续，共享记忆状态明确降级 |
| 同一事实更新 | 旧值保留失效时间，不直接抹历史 |
| confirmed 与 inferred 冲突 | confirmed 不被自动覆盖 |
| 一端遗忘 | 云端不可再检索，待发事件同步取消 |
| 错误 Token／跨 owner | 401/403，不泄露资源是否存在 |
| 云端抽取失败 | 原始 Episode 保留，错误可观测 |

真实用例：

```text
电脑：“以后总结先列结论，再列三个要点。”
手机：“我喜欢什么样的总结格式？”

手机：“我明天下午三点到东站，帮我记住。”
电脑：“我明天下午有什么行程线索？”
```

### 14.2 文件交付

| 场景 | 通过标准 |
|---|---|
| 手机要求编辑文本并回传 | 电脑生成指定版本，手机完整下载 |
| 二进制文件 Artifact | 下载后哈希与电脑快照一致 |
| 同一交付重复上传 | 返回同一 Delivery，不产生重复文件 |
| 上传中断／电脑重启 | Outbox 恢复，不出现半成品可下载 |
| 手机下载中断 | 不发送成功 ACK，可重试 |
| 撤销 Delivery | 手机后续下载被拒绝 |
| TTL 到期 | 云端临时正文物理删除 |
| 修改源文件 | 不改变已生成 Artifact 版本 |
| 非目标设备下载 | 无权访问 |
| 可执行文件 | 默认拒绝或要求额外确认 |
| 文件交付后跨端询问 | 两端知道交付事实，但记忆中没有文件正文 |

### 14.3 A2A

- v0.3 文本 Agent 合同测试通过。
- v1.0 文本 Agent 合同测试通过。
- v0.3/v1.0 文件 Artifact 均能解析为统一内部模型。
- BMA 原有澄清、计划和任务调用不回归。
- 外部 URI 指向 localhost、私网或异常重定向时被阻断。
- 文件过大、哈希不符、MIME 不支持时明确失败。
- 外部 Agent 无文本但有文件时，不再误报“没有文本结果”。

## 15. 推荐落地顺序

严格按以下顺序实施：

1. **云端共享记忆 API。**
2. **RemoteMemory、持久 Outbox 和自动召回。**
3. **旧记忆迁移与真实双端记忆验收。**
4. **Artifact 通用文件快照。**
5. **显式云端 Delivery、手机下载与回执。**
6. **A2A 版本兼容和文件产物接入。**

不要先做 A2A 文件再补本地 Artifact，也不要先做手机下载再补授权与哈希。每一阶段独立可测试、可回退，前一阶段未通过验收时不扩大范围。
