# 陪伴型 AI 管家 · 产品需求与技术方案（分期 · 全外接版）

| 项 | 内容 |
|---|---|

| 读者 | 产品、研发、算法、测试、合规 |

## 1. 定位与目标用户

**一句话定位**：用**自然语言（语音优先）**就能用的陪伴型 AI 管家——记住你提到的人、帮你盯住要做的事、到点提醒你，并提供一批高频通用的日常小能力。不要求用户懂 AI、会打字、会操作。

**三类用户与共同点**：老人 / 不接触 AI 的普通人 / 小孩，本质都是**非技术用户**，需要“零学习成本、说人话就能用”。

> 注：`user_type` **不是角色权限**——所有功能对所有用户开放，功能差异只来自用户自己说出的需求；`user_type` 仅为合规与触达策略服务（儿童监护人同意 / 内容过滤 / 夜间静默）。

| 共同点 | 设计推论 |
|---|---|
| 不会/不愿学操作 | 语音优先，交互就是“说话”和“确认/取消” |
| 不理解技术概念 | 不出现术语 |
| 出错代价高 | 高置信才自动，低置信必反问 |
| 都是“随口一说” | 核心是把口语变成结构化的人、事、提醒 |

---

## 2. 设计原则

| # | 原则 | 为什么 |
|---|---|---|
| P1 | 语音优先、零门槛 | 三类用户最大公约数是“不会用复杂产品” |
| P2 | 高置信才自动，低置信必反问 | 同名/称呼漂移/相对时间都会错，澄清成本低于记错 |
| P3 | 意图 ≠ 事实 | “说要订票”≠“已出票”，混淆会出高伤害错误 |
| P4 | 调度靠系统，不靠模型“记得” | LLM 无持久状态，提醒必须落确定性调度 |
| P5 | 事实型画像，评判标签需确认 | 自动评价既不准又有合规风险，对小孩禁止 |
| P6 | 记忆可治理 | 记错要能改能忘，否则污染后续判断 |
| P7 | 未成年人是底线 | 监护人同意/内容安全/防沉迷是法定，不是功能 |
| P8 | **能外接全外接，自建只做编排与规则** | 小团队不该重复造轮子；把精力放在“大脑”不在“体力活” |
| P9 | **可逆动作先做后问，不可逆动作先问后做** | 反问是兜底不是默认；对三类用户，反问频率本身就是体验杀手 |

## 4. 第一步 · 主要功能

> 分两组：**核心三件**（产品立身之本）+ **通用拓展**（高频、通用、不碰资金/拨号等后置项）。

**动作分级（先做后问 / 先问后做，F1–F8 通用，P9 的落地）**

| 类别 | 场景 | 规则 |
|---|---|---|
| 可逆、低风险 | 随手记、闹钟/倒计时、天气/日期、问答闲聊 | **先做后问**：直接执行，可一句话撤销（“刚才那个删了”） |
| 涉及人 | 画像写入/引用、同名消歧 | **先问后做**：置信度 < 0.8 反问（见 F1） |
| 涉及时间与行程 | 待办入列、行程类模板 | 置信度分级：≥0.85 自动可撤销 / 0.6–0.85 反问（见 F2） |
| 不可逆 | 删除/遗忘记忆、取消周期任务 | **必须确认**：回显对象，用户确认后才执行 |

### 4.1 核心三件

#### F1 人物画像（记住你提到的人）
- **为什么**：聊天里大量信息是“关于某人的”，记不住就无法在相关话题给出贴合回应。
- **做什么**：从对话抽取人物实体+别名+关系+事实，组成 wiki 式人物页；提到人时先消歧再引用。
- **关键规则**：事实型优先；不自动评价（性格/健康/财务）；置信度 < 0.8 反问消歧；冲突采信“较新且已确认”；可查看/编辑/删除/一键遗忘；**儿童仅事实型**。
- **验收**：Top-1 消歧 ≥ 90%；事实可溯源；删除后不可检索；评价性标签 0 条自动生成。

#### F2 智能待办（把随口一说变成任务）
- **为什么**：三类用户不会主动录入待办，但会随口说“我后天要订票”。
- **做什么**：抽取待办并区分**意图(intent)/事实(fact)**；相对时间归一化为绝对时间；按类型挂提醒模板。
- **关键规则**：意图只提醒“别忘了做”，事实（已出票）才触发行程模板；置信度分级入列（≥0.85 自动可撤销 / 0.6–0.85 反问 / <0.6 丢弃）；状态机持久化留痕；**周期表达**（“每天 8 点吃药”“每周三买菜”）归一化为结构化 recurrence 规则（如 `daily@HH:MM` / `weekly@WnTHH:MM`），`abs_time` 存首次触发；周期任务单次完成不终结，自动排下一次，直至取消或过期。
- **验收**：没订票不提醒赶飞机（测试集 ≥95%）；相对时间与周期表达 100% 归一化；周期任务完成单次后 100% 自动生成下一次；重启任务不丢。

#### F3 主动提醒 + 每日盘点
- **为什么**：提醒的价值在“该出现时出现”，太早打扰、太晚事故。
- **做什么**：事件驱动+持久调度；分层触达（App→推送→短信/语音）；每日盘点（默认 11:00）仅在需决策时打扰。
- **关键规则**：分级静默升级；免打扰（默认 22:00–7:00，儿童夜间一律静默）；每条提醒带【完成/推迟/取消】闭环回写；幂等防重复；**开放事项跟进**：intent 超过阈值（默认 24h 或截止前一半时间，取早者）仍未转 fact，主动追问一次（“你之前说要订票，订了吗？”）；同一事项最多追 2 次，用户说“别再问了”即停；非紧急追问并入每日盘点，不单独打扰。
- **验收**：重启/换机不丢；免打扰生效；人均推送 < 3 条/日；漏报 < 2%、误报 < 5%；已转 fact 的事项 0 误追问。

### 4.2 通用拓展（第一步新增，全外接实现）

| # | 功能 | 为什么（通用且需要） | 实现（外接） |
|---|---|---|---|
| F4 | **语音对话与陪伴闲聊** | 陪伴型产品的底座；三类用户都以说话为主 | ASR/TTS 外接（讯飞/阿里云），对话接 LLM |
| F5 | **闹钟与倒计时** | “20 分钟后叫我/明早 7 点喊我”是最高频诉求 | 复用 F3 调度；语音一句话创建 |
| F6 | **随手记 / 语音备忘** | “帮我记一下 WiFi 密码/车位在 B2” | 写入记忆系统，可语音检索“我车位在哪” |
| F7 | **天气 / 日期 / 日历** | 日常高频，老人小孩都问 | 天气外接（和风/高德）；日历内置 |
| F8 | **通用问答 / 百科** | 小孩问作业、老人问“这个啥意思” | 接 LLM 知识；儿童走内容安全过滤 |

> 取舍说明：拨号辅助、比价/支付、防诈骗**不加回第一步**（属第二步）；以上五项是真正“通用、高频、零风险”的能力，且全部可由外接服务快速实现，不增加自研负担。

**通用拓展共同规则**
1. 全部**语音可发起、语音可查询**；结果可朗读。
2. 闹钟/随手记/天气与 F2/F3 打通（随手记可转待办；闹钟本质是定时提醒）。
3. 儿童账号：问答/闲聊经内容安全过滤；夜间静默。

## 5. 第一步 · 架构（全外接）

### 5.1 架构总原则
**自建编排与规则，外接一切能力。** 凡是成熟云服务/API 能提供的（语音、LLM、向量、推送、天气、存储、监控……）一律外接，不自研；自建的只有别人给不了的“大脑”——对话编排、记忆业务逻辑、抽取流水线编排、任务状态机、澄清决策、合规与权限。

### 5.2 架构图
```
[客户端 Android / 小程序]
        |  语音/文字
        v
[接入网关] ——鉴权/限流——
        v
+-------------------------------+
| 对话编排层(自建)               |
|  意图路由 / 澄清决策 / 状态机   |
+--+----------+----------+------+
   |          |          |
   v          v          v
[NLU抽取]  [记忆系统]  [任务/调度]
(编排自建,  (逻辑自建,  (状态机自建,
 ASR/LLM外接) 向量/DB外接) 调度外接托管)
   |          |          |
   +----------+----------+
              v
   [能力外接层(全部第三方)]
   LLM / ASR / TTS / Embedding /
   推送 / 短信 / 语音 / 天气 / 地图 /
   对象存储 / 监控
```

### 5.3 外接服务清单（能力 → 外接什么）
| 能力 | 外接服务（候选） | 说明 |
|---|---|---|
| LLM 对话/抽取 | 通义 / 豆包 / DeepSeek / Moonshot API | 可插拔网关，数据合规 |
| ASR / TTS | 科大讯飞 / 阿里云语音 | 方言、老人儿童语音 |
| Embedding | 合规云 Embedding | 数据不出境 |
| 向量检索 | 托管 RDS(pgvector) / 云向量库 | 起步 pgvector |
| 数据库 | 云 RDS PostgreSQL（托管） | 不自建数据库 |
| 缓存/队列 | 云 Redis / 云消息队列 | 托管 |
| 调度 | **托管工作流**（Temporal Cloud / 云函数定时触发） | 见 5.5 取舍 |
| 推送 | 厂商通道（个推/极光）+ 微信服务通知 | 防杀后台 |
| 短信/语音 | 阿里云 / 腾讯云通信 | 高严重度触达 |
| 天气 | 和风天气 / 高德天气 | F7 |
| 地图/路程 | 高德 / 腾讯地图 | 路程反推（后续拨号/出行用） |
| 对象存储 | OSS / COS | 音频/附件 |
| 监控告警 | 云监控 + Sentry(SaaS) | 不自建监控 |

### 5.4 自建边界（只建这些）
1. **对话编排**：意图路由、澄清决策、多轮状态。
2. **记忆业务逻辑**：分层、RAG 检索排序、冲突解决、遗忘级联（底层存储外接）。
3. **抽取流水线编排**：把 ASR→LLM→归一化串起来并评估。
4. **任务状态机与提醒策略**：状态流转、分级升级、幂等。
5. **合规与权限**：监护人同意、内容过滤开关、数据治理。

### 5.5 调度的外接取舍（关键）
提醒“不丢”是硬要求。两条外接路径：
- **推荐：Temporal Cloud（托管版）**——持久工作流、重试、可恢复，天然契合“提醒→等确认→升级”，省去自建调度器运维。
- 备选：云函数定时触发 + 持久存储扫描（更省，但复杂升级流程要自拼）。
- **不采用**：纯 LLM 轮询（不可靠）、自托管 Temporal/K8s（违背“全外接/省运维”）。

## 6. 支撑系统（极简，逻辑自建/存储外接）

- **记忆系统**：分层（工作/情景/语义画像）；写前查重、高置信才写；RAG=向量召回+时间/置信度加权；可遗忘级联删；按 token 预算注入，不堆全量。底层用托管 RDS+pgvector。
- **NLU 抽取**：`ASR→清洗→意图→槽位→时间/周期归一化→置信度→澄清`；**路由兜底**：所有意图置信度均不达标时，默认由对话接住（F4 闲聊/问答），可附一句轻量反问（“是想让我记下，还是到点提醒你？”），**禁止“我听不懂”式死路**；建家庭口语评测集（方言/相对时间/同名/改口），变更必回归。
- **工具调用**：本期工具少（建任务/查记忆/发提醒/查天气/问答），走自有 Function Calling 网关（参数校验+审计）；不接外部不可信工具；**工具结果视为数据而非指令**。

## 7. 数据模型（精简，字段级）
```sql
app_user(id, user_type ENUM(elder,general,child), name, tz,
         guardian_id NULL, notif_prefs_jsonb, created_at, deleted_at)

person(id, owner_user_id FK, canonical_name, notes, created_at, deleted_at)
alias(id, person_id FK, alias)
fact(id, person_id FK, fact_type, value_text, confidence FLOAT,
     status ENUM(confirmed,inferred), source_msg_id,
     valid_from, valid_to, embedding VECTOR, created_at, updated_at, deleted_at)

task(id, owner_user_id FK, kind ENUM(intent,fact,alarm,note), schema_jsonb,
     time_expr_raw TEXT, abs_time TIMESTAMPTZ, deadline TIMESTAMPTZ,
     recurrence TEXT NULL,
     status ENUM(draft,pending_confirm,scheduled,notified,done,snoozed,cancelled,expired),
     confidence FLOAT, source_msg_id, linked_person_id FK,
     event_template, created_at, updated_at, deleted_at)

reminder(id, task_id FK, fire_at TIMESTAMPTZ, channel, level INT,
         state ENUM(pending,sent,acked,failed), dedupe_key UNIQUE, created_at)

episode(id, owner_user_id FK, summary TEXT, raw_ref, time_range TSTZRANGE,
        embedding VECTOR, expires_at, created_at, deleted_at)

audit_log(id, owner_user_id FK, actor, action, target, detail_jsonb, created_at)
consent(id, subject_user_id FK, scope, granted_by_guardian_id NULL, granted_at, revoked_at)
```
> `task.kind` 增加 `alarm`（闹钟/倒计时）与 `note`（随手记）以覆盖通用拓展；`recurrence` 存结构化周期规则（`daily@HH:MM` / `weekly@WnTHH:MM` 等），周期任务完成单次后由调度按 recurrence 排下一次。

## 8. 外接选型总表（决定 + 理由 + 放弃项）

| 能力 | 决定 | 理由 | 放弃项与原因 |
|---|---|---|---|
| LLM | 国内合规云 API（可插拔） | 合规、可替换、控成本 | 自研/自托管：重；海外模型：出境 |
| ASR/TTS | 讯飞 / 阿里云语音 | 方言+老人儿童语音成熟 | 自研：周期长 |
| 向量/DB | 托管 RDS PostgreSQL + pgvector | 关系+向量一体、删除即真删、免运维 | 自建库/独立向量库：运维重 |
| 调度 | Temporal Cloud（托管） | 持久可恢复、省运维 | 自托管 Temporal/K8s：违背全外接 |
| 推送 | 厂商通道 + 微信服务通知 | 到达率、防杀后台 | 仅 App 内 Push：杀后台失效 |
| 天气/地图 | 和风/高德 | 成熟 API | 自建数据源：没必要 |
| 存储/监控 | OSS/COS + 云监控 + Sentry | 免运维 | 自建监控：重复造轮子 |
| 客户端 | Android Kotlin 原生首发 | 语音/通知/保活稳，老人机覆盖好 | 纯小程序首发：后台能力弱 |

## 9. 合规要点
- **通用（PIPL）**：最小必要、敏感信息加密（KMS）、画像与记忆可查/改/删、可溯源可审计。
- **未成年人（底线）**：不满 14 周岁须监护人同意；内容安全过滤；防沉迷；儿童画像仅事实型，监护人可查看删除；遵循《未成年人保护法》网络保护要求。
- **适老化**：参考《移动互联网应用适老化通用设计规范》。

## 附：一页结论
- **第一步做什么**：核心三件（画像/待办/提醒盘点）+ 通用拓展（语音对话/闹钟倒计时/随手记/天气日历/问答），三类非技术用户可用。
- **怎么建**：**能外接全外接**（语音/LLM/向量/推送/天气/存储/监控全用云服务），自建只做“编排与规则”（对话编排、记忆逻辑、抽取流水线、任务状态机、合规权限）。
- **两条底线**：调度靠确定性系统不靠模型“记得”；未成年人是法定合规不是功能。
- **分期**：第一步跑通后，第二步“带路办事”、第三步“家庭协同”再立项。
