## 一、项目概述

金手指管家是一个用 Go 编写、可在 Android 手机本地与服务器运行的 AI 管家。它以自然语言（语音优先）为交互方式，帮助用户：**记住人与事、管理待办与提醒、在信息出现的瞬间替用户接住、并按语义找回历史消息**。

同一内核兼顾三类非技术用户：**老人（elder）、普通人（general）、小孩（child）**。核心设计原则是「**高置信才自动，低置信必反问**」，追求零学习成本与可解释性。

### 一句话定位（当前）
不挑手机品牌、能在「通知层」替人接住信息并盯到办完的本地 AI 管家。

### 产品演进方向（来自竞品深调，见 [./archive/竞品深调报告.md](./archive/竞品深调报告.md)）
- 厂商把家庭守护圈在同品牌生态内（品牌墙），诈骗从通话迁移到 App 内/屏幕内。
- 中期方向：**跨品牌的家庭安全纽带**（实时语义守卫 + 就医/用药流程卡片 + 子女端协同）。
- 当前 v0.2 先把高频「通知层」能力做扎实，作为后续一切的底座。

## 二、功能全景

### 2.1 对话与任务（v0.1）
- 自然语言多轮对话、语音输入（ASR）、语音播报（TTS）。
- 工具调用循环：模型按需调用工具，观察结果后再决策。
- 任务管理：创建、确认、到点提醒、完成、取消、过期。
- 闹钟 / 随手记 / 天气 / 通用问答等日常小能力。

### 2.2 记忆（v0.1）
- 人物画像（含别名、消歧）、事实记忆、事件片段。
- 向量语义检索 + 关键词检索，记忆上下文按 token 预算裁剪注入。
- 记忆可查看/编辑/删除/一键遗忘（级联硬删向量），事实可溯源。
- `GET /api/memory/export.md` 导出人可读的 Markdown 记忆档案。

### 2.3 通知中心（v0.2 新增，本报告重点）
一条统一「通知通道」，支撑四个高频功能：

| 功能 | 说明 | 触发/入口 |
|---|---|---|
| **稍后处理（snooze）** | 通知到达时一键「10 分钟后/1 小时后/今晚再看」，到点把**原文**弹回 | 安卓社交通知 action；HTTP |
| **线索自动接住（clue）** | 自动识别取件码/验证码/运单号，结构化入库、一键复制 | 通知上报时正则提取 |
| **语义搜索（search）** | 按意思找回历史通知（"老王上次发我的地址"），无向量时显式降级关键词 | Web 收件箱搜索框 |
| **等到了（watch）** | 创建等待项（联系人+关键词+可选来源），命中即高优通知 | Web 表单；HTTP |

> MVP 边界：地理围栏（到驿站弹码）、降价/屏幕行为观察、通话反诈本期不做。

### 2.4 合规与安全（v0.1）
- 儿童内容门控、监护人同意、事实类型策略、审计日志。
- 工具结果包固定前缀当「数据」处理，防御 prompt injection。
- 屏幕上报对支付/密码等敏感界面有 FLAG_SECURE 检测与 SafetyGuard。

## 三、系统架构

### 3.1 分层（照抄 pi agent 的分层思想，Go 精简实现）

| 层 | 目录 | 职责 |
|---|---|---|
| 接入层 | `cmd/server`、`internal/httpapi` | HTTP/WS、JSON DTO、静态页托管 |
| 编排层 | `internal/agent` | 工具调用循环、会话状态、提示词组装、待决项处理 |
| 能力层 | `internal/llm`、`internal/extsvc` | LLM/ASR/TTS/推送/短信/天气的统一接口与 Stub |
| 领域层 | `internal/nlu` `memory` `task` `scheduler` `compliance` `intent` `inbox` | 抽取、记忆、任务、调度、合规、意图、通知中心 |
| 持久层 | `internal/store`、`migrations` | SQLite 仓储、迁移、应用层向量运算 |
| 设备层 | `android/`、`internal/device` | 无障碍服务、通知监听、屏幕通道 |

### 3.2 部署形态
- **服务端模式**：`cmd/server` 单进程，托管 API + Web UI；SQLite 单文件，`CGO_ENABLED=0`（纯 Go，modernc.org/sqlite）。
- **安卓端模式**：APK 内通过 gomobile 运行 Go 服务（`android/gosvc`），App 以无障碍 + 通知监听作为设备能力，WebView 承载 UI。
- **能外接全外接**：LLM（OpenAI 兼容，含 Responses 协议）、ASR/TTS/推送/短信/天气均为接口 + Stub，换供应商只改 `base_url`。

### 3.3 通知中心数据流（v0.2）

```
Android 通知
   │ (NotificationListenerService，旁路、不取消原通知)
   │  防回环(过滤自身包名) + 60s 去抖
   ▼
POST /api/inbox/events ─► Ingest:
   1) hash(pkg+title+text+分钟桶) 去重 (Insert OR IGNORE)
   2) 线索正则提取 → kind=clue
   3) armed watches 匹配 → 命中: status=fired + Outbox「等到了」
   4) embed (失败 → embedding=NULL，不报错)
   ▼
SQLite: inbox_event / inbox_snooze / inbox_watch
   ▼
30s Due 循环: snooze 到期 → 置 fired + Outbox.Push
   ▼
Outbox (内存) ─► NotifyPoller 每 10s GET /api/outbox
   ▼
系统通知（原文弹回 / 等到了）
   ▲
Web 收件箱: search / snooze / clue / watch 面板 (经 /api/inbox/*)
```

要点：**LLM 不参与通知捕获**（快、省电、稳），仅用于语义检索（embedding）。

## 四、关键技术决策

1. **全外接 + Stub**：核心能力接口化，CI 不依赖外网与真实 API。
2. **置信度分级自动化**：任务 ≥0.85 自动（可撤销）/ 0.6–0.85 反问 / <0.6 丢弃；人物消歧 <0.8 反问。阈值集中管理。
3. **意图 ≠ 事实**：intent 只提醒"别忘了"，fact 才触发行程类提前量。
4. **相对时间 100% 归一化**：自研规则解析器 `internal/nlu/timecn` + LLM 兜底（硬校验 RFC3339/未来时间/recurrence）。
5. **任务 8 态状态机 + CAS 迁移**：宁紧勿松，非法迁移报错。
6. **调度策略**：免打扰 22:00–7:00、分级升级（App→推送→短信/语音）、推送预算、每日盘点。
7. **向量为定长 1024 维 BLOB**（小端 float32，默认 bge-m3）；应用层余弦，embedder 缺失时**显式降级**（mode 如实回传），不静默。
8. **通知监听旁路设计**：绝不 cancel/改写原通知，独立 channel 转述，避免破坏原 App 行为。

## 五、数据模型（v0.2 新增表）

迁移文件：[`../migrations/0004_inbox.sql`](../migrations/0004_inbox.sql)

- **inbox_event**：通知事件。`id`、`owner_user_id`、`source_pkg`、`app_name`、`title`、`text`、`kind(normal|clue)`、`clue_type`、`clue_value`、`posted_at`、`ingested_at`、`dedupe_hash`、`embedding`；`UNIQUE(owner_user_id, dedupe_hash)` 去重。
- **inbox_snooze**：稍后处理。`id`、`owner_user_id`、`event_id`、`fire_at`、`status(pending|fired|cancelled)`、`created_at`。
- **inbox_watch**：等待规则。`id`、`owner_user_id`、`title`、`keyword`、`source_pkg`、`status(armed|fired|cancelled)`、`created_at`。

其余表（app_user / person / alias / fact / task / reminder / episode / standing_intent / audit / consent / chat_session / chat_message）见 `migrations/0001–0003`。

## 六、HTTP API 概览

通知中心端点（完整字段见 [API 手册](./API手册.md)）：

| 方法 路径 | 功能 |
|---|---|
| POST /api/inbox/events | 批量上报通知 |
| GET /api/inbox/events | 查询事件（kind/limit） |
| GET /api/inbox/search | 语义/关键词搜索 |
| POST /api/inbox/snooze | 创建稍后处理 |
| GET /api/inbox/snooze | 查询稍后处理（join 原文） |
| POST /api/inbox/watches | 创建等待项 |
| GET /api/inbox/watches | 查询等待项 |
| DELETE /api/inbox/watches/{id} | 取消等待项 |

约定：JSON；时间 RFC3339；`Inbox` 服务未装配时统一返回 503。

## 七、测试与质量

- 运行：`go vet ./... && go test ./... -count=1`（全部包通过）。
- 测试策略：
  - 表驱动 + 边界值（置信度 0.85/0.84/0.6/0.59、时间归一化跨日跨月）。
  - 状态机全迁移矩阵、DND/升级/预算策略。
  - 脚本化 LLM（`llm.ScriptedClient`）+ 假时钟 + SQLite 内存库，CI 不烧 API、不连外网。
  - 通知中心 26 例：线索三类正反例、watch 命中/未命中、snooze 到期置 fired、去重、无 embedder 时 `mode=keyword`、vector 与降级、八端点契约 + 503。
- 约束：单文件体量受控（inbox 最大 372 行），不改既有领域行为。
