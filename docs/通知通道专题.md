## 一、为什么做通知层

真实生活里，人在信息到达的瞬间常常手没空（开车、抱孩子、开会），"等一下再说"之后事情就掉了。系统闹钟/日历要求人先把事情翻译成时间和文字，门槛高；通用 AI 助手又无法跨 App 捕获信息。

通知是 Android 上**所有 App 信息的共同出口**。在这一层做「接住、暂存、追踪、找回」，是 OpenClaw（太重）、系统语音助手（不能跨 App）、系统闹钟（记不住内容）都没占住的位置。

设计原则：
- **旁路监听，不破坏原 App**：绝不 cancel/改写原通知，只新增自己的转述通知。
- **LLM 不参与捕获**：捕获/提取/匹配走规则，快、省电、稳；LLM 只用于语义检索。
- **降级显式**：没有向量能力时明确标注关键词模式，不静默失效。

## 三、四个功能的行为规格

### 1. 稍后处理（snooze）
- 入口：微信/短信等社交白名单通知，由本 App 发「通知助手」转述，附 action：`10 分钟后` / `1 小时后` / `今晚`。
- `今晚` = 当天 20:00；若当前已过 20:00，则次日 20:00。
- 点 action → Receiver 回查该通知对应的 event_id（GET /events 按 pkg+title+text 精确匹配取最近一条）→ POST /snooze。
- 到点：30s Due 扫描 → 置 fired → Outbox → 系统通知把**原文**弹回。
- 匹配不到 event_id 时静默不发，避免误绑。

### 2. 线索自动接住（clue）
通知入库时按正则提取，命中则 `kind=clue`：

| clue_type | 识别关键词 | 取值 |
|---|---|---|
| pickup 取件码 | 取件码/取货码/提货码/取件密码/菜鸟/驿站 | 4–8 位数字（可带 - 尾号） |
| code 验证码 | 验证码/校验码/动态码/确认码 | 4–8 位数字 |
| tracking 运单号 | 运单/快递单号/物流单号 | 字母前缀 + 10–15 位数字 |

- Web 线索 tab 可一键复制 `clue_value`。
- 正则口径集中在 `internal/inbox/clue.go`，误判/漏判以新增用例方式维护，而非堆叠临时规则。

### 3. 语义搜索（search）
- 对查询文本做 embedding，与事件 `embedding` 算余弦排序。
- embedder 缺失/失败/事件无向量时 → `mode=keyword`，对 title+text 做 LIKE。
- 结果中 `mode` 必须如实呈现（Web 显示"语义/关键词"徽标）。

### 4. 等到了（watch）
- 创建等待项：title（人/主题）+ keyword（必含）+ source_pkg（可空=不限 App）。
- 每条新通知入库时与 armed watches 匹配：来源一致（或不限）且包含 keyword → watch 置 fired + Outbox 高优通知「等到了：…」。
- 可在 Web 取消（DELETE）。

## 四、权限与合规

- 需要「通知访问权」（BIND_NOTIFICATION_LISTENER_SERVICE）。引导在 `PermissionsActivity` 第 5 张卡片，跳转 `ACTION_NOTIFICATION_LISTENER_SETTINGS`。
- 通道：
  - 「通知助手」IMPORTANCE_DEFAULT：社交转述，不响铃骚扰。
  - 「管家提醒」IMPORTANCE_HIGH：到点 / 等到了，可响铃震动。
- 隐私：通知文本含敏感信息，云端 LLM 仅接收用于 embedding 的文本；产品化前需补脱敏与外传告知（见路线图 v0.3）。
